# dogapp

Рабочий мессенджер на чистом **HTML + CSS + JS** без сборки, фреймворков и платных подписок.
Версия 3.0: обязательная регистрация, только реальные аккаунты, управление серверами, друзьями, звонками и полное удаление аккаунта.

## Главное отличие версии 3.0

- В базе нет готовых серверов, ботов, вымышленных людей, подставных сообщений и заявок.
- Гостевого входа больше нет. Первый экран — регистрация. Без аккаунта интерфейс недоступен.
- Все серверы, каналы, сообщения, эмоции, друзья и звонки создаются зарегистрированными людьми.
- При обновлении со старой версии запускается очистка: старые серверы, профили без аккаунта, сообщения от них, реакции и ссылки удаляются из Firebase RTDB и локального кэша.
- Звонки работают только через WebRTC и только между зарегистрированными аккаунтами. Локальных заглушек, выдуманных собеседников и синтетического видео нет.

## Что умеет

| Фича | Как работает |
| --- | --- |
| Регистрация и вход | Полноэкранная форма «Регистрация / Вход»: имя, логин, пароль. Аккаунт в `/dogapp/accounts/<login>` (соль + SHA-256 в браузере), профиль в `/dogapp/users/<uid>`, сессия в `localStorage`. Гостей нет. |
| Выход и удаление аккаунта | Кнопки есть в нижней панели пользователя и во вкладке «Аккаунт». Удаление требует пароль и точное подтверждение логина. Удаляются аккаунт, профиль, друзья, заявки, блокировки, ЛС, сообщения, реакции, звонки, присутствие и набор текста. Сервер без других участников удаляется; сервер с участниками передаётся другому владельцу. |
| Интерфейс | Рельса серверов, каналы с категориями, чат, список участников, ЛС, профили, настройки, адаптивная вёрстка в стиле Discord. |
| Серверы | Создаются только пользователями: название, описание, фото или монограмма, баннер, текстовые и голосовые каналы, участники, роли владельца и участника, настройки и удаление. |
| Друзья | Заявки, принятие, отклонение, отмена, удаление, блокировка и поиск по логину или имени. В списках участвуют только аккаунты из `/dogapp/accounts`. |
| Звонки | 1:1 голосовые и видеозвонки через **WebRTC**. SDP и ICE пишутся в Firebase RTDB, состояние подтягивается опросом. Есть входящий вызов, микрофон, камера, таймер и завершение. Если браузер не дал доступ к устройствам, звонок не создаётся. |
| Голосовые каналы | Подключение, список реальных участников, микрофон, звонок участнику и отключение. Присутствие в `/dogapp/voice/<channelId>/<uid>`. |
| Выбор фото | Аватар и баннер: файл с устройства, ссылка или градиент. Переключатель «Анимация»: GIF/WEBP без галочки замораживается в первый кадр PNG, с галочкой сохраняется движение; для градиента включается плавное движение. |
| Шрифт ника | Восемь начертаний с предпросмотром. Выбор сохраняется в профиле и виден всем в чате, участниках, профилях и друзьях. |
| Эмоции серверов | Свои `:name:` значки из файла или по ссылке, анимация и доступ друзьям. Это нейтральные векторные монограммы, а не смайлы. Общий picker по всем серверам и вкладка типографских символов. |
| Баннеры | Фото или градиент у профиля и каждого сервера: шапка, интро канала, профиль, карточки и страница приглашения. |
| Приглашения | Вечная кастомная ссылка `dogapp.gg/<адрес>` или обычная ссылка со сроком **ровно 3 дня**. Страница `#/i/<code>`, просроченные ссылки блокируются. Приглашение без аккаунта сначала показывает регистрацию и сохраняет код. |
| Realtime | Узел `/dogapp` в Firebase Realtime Database через REST (`GET/PUT/PATCH/DELETE`), опрос раз в 2 секунды. При недоступности сети включается локальный кэш браузера с синком между вкладками. |
| Прочее | Реакции, ответы, редактирование, поиск, «печатает…», вложения, вставка картинки по ссылке, каналы, онлайн-статусы, настройки подключения. |

Декоративные смайлы в интерфейсе не используются. Аватары и иконки серверов — монограммы, эмоции серверов — векторные значки, логотип нарисован в SVG.

## Запуск

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

Откройте `http://localhost:8000` или preview-ссылку. Нужен именно HTTP: ES-модули не работают с `file://`. Подойдёт любой статический хостинг.

## Firebase

База прописана в `js/util.js`:

```
https://dogapp-52b84-default-rtdb.firebaseio.com
```

Данные в узле `/dogapp`. Адрес меняется в интерфейсе: «Настройки пользователя → Подключение».

Правила базы для работы без серверной авторизации (Firebase Console → Realtime Database → Rules):

```json
{
  "rules": {
    "dogapp": {
      ".read": true,
      ".write": true
    }
  }
}
```

Для рабочего проекта с закрытыми данными добавьте Firebase Authentication и проверки `.validate`. Текущая схема хеширует пароль на клиенте и хранит аккаунт в RTDB; это рабочая регистрация для статического приложения, но не замена серверной аутентификации.

При первом подключении к пустой базе создаётся только пустая структура узлов. Никакие серверы и участники не заливаются.

## Структура

```
index.html          каркас: загрузка, регистрация, приглашение, рельса, сайдбар, чат, оверлеи
styles.css          интерфейс, экраны аккаунта и звонков, адаптив
assets/logo.svg     логотип dogapp
js/util.js          экранирование, URL/цвета/баннеры, файлы и freeze GIF, шрифты, хеш пароля, проверка аккаунта
js/icons.js         SVG-иконки
js/emojis.js        эмоции серверов и нейтральные символы
js/seed.js          пустое состояние и очистка данных старых версий
js/store.js         REST-клиент Firebase, пакетные изменения, локальный кэш
js/auth.js          регистрация, вход, сессия, выход, удаление аккаунта, экран входа
js/friends.js       заявки, список друзей, поиск, блокировка, экран «Друзья»
js/calls.js         WebRTC-сигналинг и голосовые каналы
js/render.js        рендер чата, форматирование текста, карточки приглашений
js/modals.js        настройки, приглашения, эмоции, каналы, профили, удаление аккаунта, picker
js/app.js           события, экшены, формы, загрузка фото, роутинг #/i/<code>
```

## Горячие клавиши

- `Enter` — отправить сообщение
- `Shift + Enter` — новая строка
- `Esc` — закрыть окно / picker / отменить ответ

## Примечания

- Сессия хранится в браузере; при входе под тем же логином и паролем с другого устройства подтягивается тот же uid и профиль из Firebase.
- Кастомные ссылки — hash-роуты `#/i/<code>`, поэтому работают на любом статическом хостинге.
- WebRTC использует публичный STUN-сервер. Разрешение на камеру и микрофон запрашивает браузер; нужен HTTPS или localhost.
- Синтаксис сообщений: `**жирный**`, `*курсив*`, `` `код` ``, `> цитата`, `@Имя`, `:emote:`, `![подпись](https://…/pic.png)`, ссылки.
